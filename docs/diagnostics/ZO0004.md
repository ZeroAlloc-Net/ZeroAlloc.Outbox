# ZO0004 — Generic OutboxMessage Type Has No Closed Usage

**Severity:** Warning

`[OutboxMessage]` is applied to a generic type, and no closed construction of it is used or declared in the same assembly. Outbox code is generated per closed construction, such as `Envelope<Order>`, so none is generated for the type.

---

## Example

```csharp
namespace MyApp;

// ZO0004: no IOutboxWriter<Envelope<...>> and no [assembly: OutboxMessage(typeof(Envelope<...>))]
[OutboxMessage]
public sealed record Envelope<T>(string CorrelationId, T Payload);
```

---

## How to fix

Use the writer or dispatcher of a closed construction, and the generator finds it:

```csharp
public sealed class Checkout(IOutboxWriter<Envelope<Order>> writer) { /* ... */ }
```

Or declare the closed construction on the assembly, for example in an assembly that only dispatches:

```csharp
[assembly: OutboxMessage(typeof(Envelope<Order>))]
```

A usage that is still open, such as `IOutboxWriter<Envelope<T>>` inside a generic method, does not count. See [Generic message types](../message-types.md#generic-message-types).

---

## When to suppress

When the generic type is not used as a message yet and you want to keep it. Every closed construction must be used or declared in the assembly that declares the generic type, because the generator emits code only there, so a construction closed only in another assembly still gets no code.

```csharp
#pragma warning disable ZO0004
[OutboxMessage]
public sealed record Envelope<T>(string CorrelationId, T Payload);
#pragma warning restore ZO0004
```
